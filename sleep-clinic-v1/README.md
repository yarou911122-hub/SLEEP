# 睡眠門診個案管理系統 V1｜依需求簡報製作

此版依使用者提供的 37 頁需求簡報，實作 R01–R06 的假資料前端操作原型。保留原生 HTML／CSS／JavaScript、低彩度灰綠配色與大字級，首頁改為以到期待辦為主；個案頁以分頁降低同頁資訊量。

## 開啟方式

1. 將 ZIP「解壓縮全部」。這是新版獨立資料夾，不必覆蓋原本專案。
2. 在 VS Code 選「檔案 → 開啟資料夾」，選取 `sleep-clinic-v1-requirements`。
3. 開啟 `index.html`，按 Go Live，或右鍵選 Open with Live Server。
4. 輸入示範帳號與密碼即可操作。

也可直接雙擊 `index.html`，但建議使用 Go Live，以穩定使用本機資料保存。直接開檔與 Go Live 的資料不共用。

| 角色 | 帳號 | 密碼 |
| --- | --- | --- |
| 個案管理員 | `demo_manager` | `demo1234` |
| 系統管理員 | `demo_admin` | `demo1234` |

登入僅為介面模擬，重新整理後需再登入；並非真正的身分驗證。兩個角色均可操作 R02–R06；管理員另外可調整示範日期、重設資料與查看本機操作紀錄。個管直接開啟設定網址也會顯示無權限提示，但前端限制可被繞過，不能作正式權限保護。

## 需求與實作對照

| 簡報需求 | 此版操作 |
| --- | --- |
| R01 帳號與角色 | 示範登入、錯誤重試、角色導覽與設定頁限制 |
| R02 收案與個案管理 | 姓名／識別碼搜尋、狀態篩選、查無資料後新增、必填與重複檢查、編輯基本資料 |
| R03 門診追蹤與諮詢 | 歷次時間軸、新增諮詢與下次追蹤、回診新增／修改／取消與完成 |
| R04 評估表單 | 新增表單追蹤、示範連結複製、人工傳送日期與確認日期、人工核對勾選 |
| R05 首頁與待辦 | 三類可點擊摘要、到期清單、今日回診、類型／日期／完成狀態篩選 |
| R06 LINE 人工聯繫 | 個案聯繫紀錄、管道／事項／結果／備註，保存後同步待辦與摘要 |
| R07 自動化與院內介接 | 未啟用，只在管理員頁說明第二階段範圍 |

主方案採用簡報的工作摘要、個案清單及分頁詳細資料，不將替代首頁與週曆同時堆入導覽。第一版不提供個案自行預約或實際填答表單。

## 先走一次核心流程

示範工作日固定為 **2026-11-25**。登入後初始首頁數量為：待聯繫 1 件、待表單確認 1 件、待回診提醒 1 件。

1. 首頁選「待聯繫」，會看到個案 C 的「確認首次看診時間」。
2. 按「處理待辦」，查看對象與事項，再選「登錄聯繫結果」。
3. 用虛構內容示範聯繫，處理結果選「已處理」，勾選已實際完成並儲存。
4. 畫面進入個案聯繫紀錄，顯示剛才的結果與建立者／時間。
5. 回到首頁，「待聯繫」會由 1 變成 0。

這是模擬人工聯繫後的登錄流程。網站不會替你發 LINE，不會推定對方已讀。

## 其他驗收任務

### 個案與重複檢查

- 搜尋 `DEMO-001`，只顯示個案 A。
- 搜尋 `DEMO-005`，查無資料時出現新增按鈕。
- 新增時把識別碼改成 `DEMO-001`，儲存應提示已存在，並保留表單輸入。
- 改回 `DEMO-005`，填寫虛構姓名，保存後顯示個案明細。
- 編輯基本資料，確認更新後可回看。

### 追蹤與回診

- 在個案的「追蹤與回診」新增諮詢，日期、內容為必填；填寫下次追蹤日期會產生一般聯繫待辦。
- 新增回診安排，會產生前一天的提醒。回診清單可查看。
- 修改回診時間或地點，對應提醒重新開啟。
- 將回診改成已取消／已完成，對應提醒關閉；恢復已安排會重新開啟。

### 表單人工確認

- 在個案 B 的評估表單點「示範連結」。連結使用 `example.invalid` 保留域名，不能實際填答；不含個案識別碼，不會連上外部服務。
- 複製連結後，狀態不會自動變動。
- 選「已確認」但未勾選人工核對或未填確認日期，應拒絕儲存且保留輸入。
- 填日期並勾選後儲存，對應表單待辦完成，首頁摘要更新。
- 將已確認表單改回待確認，對應待辦重新開啟。

### 待辦、角色與保存

- 待辦清單可查看已處理項目；一般聯繫與提醒可填原因重新開啟。
- 表單待辦的完成／重新開啟由評估狀態控制，避免僅傳送連結就完成。
- 重新整理網站並重新登入，確認新增的假資料仍存在。
- 個管直接進入 `#settings`，應顯示僅供管理員使用。
- 管理員可調整示範工作日，或經確認後恢復預設四筆假資料。
- 縮窄視窗：導覽改成上方橫向捲動，卡片改為單欄，表格在區塊內橫向捲動。

## 保存與例外處理

- 資料以 localStorage 保存在同一瀏覽器、同一網站來源。更換電腦、瀏覽器或 Go Live 連接埠，會看見不同資料。
- 清除網站資料、無痕視窗關閉或管理員重設可能移除資料；沒有雲端同步或備份。
- 儲存流程先建立副本，再檢核並保存；成功後才更換畫面資料。
- 本機保存失敗時，表單維持開啟、保留輸入並顯示提示，可處理問題後重試。
- 取消／關閉表單不保存輸入。本機操作紀錄供示範回看，可由瀏覽器修改，並非正式稽核。

## 目前採用的暫定規則

- 首頁摘要只計入示範工作日以前（含當日）到期且未完成的待辦；未來待辦仍可從個案頁或全部日期查看。
- 「待聯繫」卡包含一般聯繫與回診確認；表單與回診提醒分開計數。
- 「等待回覆」仍屬未完成；完成聯繫需人工勾選確認。
- 表單「已確認」需人工查閱勾選及確認日期，不做自動計分。
- 收案識別碼固定以 `DEMO-` 開頭。沒有病歷號自動帶出姓名、院內匯入或正式身分綁定。
- 已結案狀態目前只供分類，不自動取消回診或待辦。管理員與個管的正式異動權限仍待確認。

上述規則是讓原型可驗收的暫定決策，應再與老師及實際個管確認，不代表院方已核定。
